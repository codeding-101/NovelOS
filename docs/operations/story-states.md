# 结构化故事状态与时点查询

适用版本：schema `0012_story_states`。在已有记忆提案、来源与人工审核流程上，增加可选结构化状态。所有操作在本地平台完成，不调用外部模型，不改变正文或定稿状态。

## 填写与查询

在“记忆与审核”中新建或修改提案，勾选“指定故事状态与生效区间”，填写对象标识、状态属性、状态取值和时点。例如对象 `人物-林舟`、属性 `职业`、取值 `船医`，生效区间 `[10, 20)`。

时点是作品内部约定的非负整数，最大为 10¹²，按故事实际发生顺序排列；不是章节序号、发布时间或审核日期。用户须自行保持同作品的时点单位及对象／属性名称一致。平台不解析日期、推断年表或识别人名别称。倒叙和插叙可查询较早时点，不需要改变章节顺序。

开始时点包含在区间内，结束时点不包含，结束必须大于开始；留空表示持续有效。上例在 10、19 生效，在 20 不生效。持续一个时点的事件可约定为 `[10, 11)`，这仅表示用户指定的离散区间，不证明事件实际持续多久。

提交仍是候选，只有用户批准后才进入“故事时点查询”。可按时点查询全部对象，或填写对象标识精确匹配；网站每页 20 项，API 每页最多 100。界面注明已应用的时点和筛选条件，重新查询获取最新审批。来源后来更新的正式状态保留并标记需复查，不自动撤销事实。

## 版本与时间是两个维度

时点查询使用各记忆标识当前批准的版本。历史版本用于核对旧审核，绝不因查询过去时点而重新成为现行设定。当前版本未覆盖某个时点时，不会从该条目的旧版本补值。

要保留人物的两个职业阶段，应使用两个条目，例如“林舟-早期职业” `[0, 20)` 和“林舟-后期职业” `[20, 无结束)`；它们的对象和属性相同。若早期职业原本没有结束时点，先提出修改、补上结束 20 并批准，再批准后期职业。提案的“提出修改”是对该条目设定的修正，不是自动追加故事事件。

修改提案会预填原结构化状态，审核详情及版本历史展示修改前后区间和取值。取消勾选并获批，表示当前条目不再提供结构化时点信息；旧状态仍保留于审核历史。无结构化状态的文字条目继续显示在正式记忆中，但不参加时点查询。查询没有结果不等于平台证明该时点没有事实。

## 区间冲突与审核

同一作品、对象标识与属性在一个时点最多对应一个正式条目。不同标识的区间重叠时，即使取值相同也阻止批准；相邻区间允许衔接。不同对象、不同属性、不同作品互不冲突。对象、属性和取值会去除首尾空白，但不做语义归一；别名、同义词和跨属性矛盾仍须人工核对。多值状态应明确组织为同一条目的取值，本版不做多值关系推理。

存在重叠的提案仍可保存用于审查，详情显示 `STORY_STATE_OVERLAP` 及至多 20 个重叠条目。可以驳回，或先修正其他现行条目的区间再刷新；若其余来源、依据及期限仍有效，可继续批准。审批在作品锁下重新校验，两个不同标识的并发提案也不能同时建立重叠正式状态。修改自身条目时，排除它将被替代的旧状态，但仍检查所有其他现行条目。

原有来源、版本和过期检查继续生效，源文已变不能靠补时点绕过审核。来源待复查的现行状态仍占用原区间，避免未经决策悄悄引入第二个版本。结构化状态与提案、来源在同一事务保存，并受数据库不可修改／不可删除保护；批准、正式指针及审计仍一次提交。

## API 与迁移

`POST /api/v1/works/{work_id}/memory/proposals` 新增可选 `story_state`，省略或传 null 保持文字提案行为：

```json
{
  "subject_key": "人物-林舟",
  "predicate": "职业",
  "value": "船医",
  "valid_from": 10,
  "valid_until": 20
}
```

对象与属性各最多 128 字符，取值最多 1024 字符，不接受空白值。写入时点须为整数，不接受布尔值、字符串和小数。记忆详情新增 `story_state` 和 `story_conflicts`；既有创建幂等键将状态计入内容指纹，不能用同键修改区间。

`GET /api/v1/works/{work_id}/memory/timeline?at=10&subject_key=人物-林舟&offset=0&limit=20` 返回当前正式且覆盖该时点的条目。`at` 必填，对象可省略，按对象、属性、记忆标识稳定排序。只有用户会话可读写；Agent 令牌不能访问。创建和审核仍要求 CSRF 与合法来源。

升级前停止 API／Worker，备份独立平台库，按 [部署指南](platform-setup.md) 显式迁移。`0012_story_states` 只新增不可变状态表及索引；旧提案、决定、来源和正式指针不改动，不补造故事时间，旧请求幂等键保持兼容。迁移不提供破坏性降级，恢复旧版本须使用升级前备份。

本版不包含角色知情范围、平行时间线、历法、自动抽取、实体合并、语义冲突分析或批量批准。分层摘要、上下文快照及容量检查、审批规则与正式正文提交仍是后续工作包。设计见 [ADR 0012](../decisions/0012-story-states.md)。
