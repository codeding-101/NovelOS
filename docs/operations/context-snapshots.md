# 上下文快照与容量检查

快照基础始于 schema `0013_context_snapshots`，当前 `0014_task_contexts` 已加入可选任务绑定。快照用于固定目标、正文、选定正式记忆和来源，核对容量及版本依据；保存或复查本身不会触发调用、消费或正文定稿。执行绑定见 [任务上下文](task-contexts.md)。

## 网站流程

从控制台进入“上下文快照”，选择作品，填写名称、任务目标、输入正文版本和容量上限。可指定目标故事时点，再检索正式记忆并逐项加入。默认标为必需；取消必需标记后成为可选，前移按钮调整选择顺序。最多选择 50 个不同提案版本。

“按相关性推荐”会结合关键词与目标故事时点查找来源有效的记忆，展示匹配依据；点击“推荐加入”才纳入选择。修改查询条件后需重新推荐，原字面检索仍独立可用。推荐不保证核心设定齐全，保存时仍会再次核对来源，详见 [检索与推荐说明](memory-retrieval.md)。

任务目标、完整输入正文、基础引用信息始终必需。正式记忆由用户明确选择，平台当前不会推断哪些核心设定必须加入；未选条目不属于本次快照范围。候选、驳回、已替代或其他作品的记忆不能作为选择输入，网页只展示现行正式记忆。新设定未先经过审核，不能借助快照直接成为正式事实。

点击“保存上下文快照”后可查看保存时状态、必需／组装字节数、SHA-256、纳入与省略清单、原文及来源版本。容量不足或依据不适用也可形成不可变的阻断记录，供用户调整配置；不会伪装成成功。修改表单并再次保存会生成新快照，旧快照和原文保持不变。相同请求标识、相同配置重试返回原记录，修改配置使用新请求标识。

“重新核对快照依据”会在检查时重新核对所纳入版本并写审计。先前显示已组装的快照，来源后来改变仍会在详情标记失效；不会改写保存时状态、文档或哈希。网页冲突和请求失败保留表单输入；重新选择当前版本后可另建快照。

## 容量与取舍规则

容量单位是序列化快照文档的实际 **UTF-8 字节**，范围 1 至 8 MiB。计数包括目标、输入、记忆内容、结构化状态及所携带的 ID、来源哈希等 JSON 信息，也包括转义与分隔符；中文不能按一个字符一个字节计算。

该数值不是供应商 token 数，也不是某个模型窗口保证。任务绑定后的本机协议消息已将完整快照纳入既有容量代理与输出预留检查；提供者真实分词和窗口保证仍需后续适配。不拿字节数冒充真实 token，亦不修改供应商预算规则。

组装规则：

1. 固定完整输入和所有必需记忆。必需记忆按选择顺序保留；不裁切正文、条目或引用。
2. 检查必需内容容量和依据。超限或失效时保存 `BLOCKED`，完整必需内容继续保留用于诊断，因此阻断文档本身可能大于设定上限。此时不再组装可选条目。
3. 必需内容通过后，依选择顺序逐项尝试可选记忆。只加入完整且适用、来源有效并能容纳的条目；过大条目省略，继续尝试后续较小条目。清单为每个未加入条目记录原因。
4. 所选可选条目全被省略时，只要必需内容有效且能容纳，仍可为 `READY`。必须查看省略清单；`READY` 表示本次组装通过，不证明选择范围完整或小说事实一致。

保存的 `document` 是紧凑、键排序、未额外转义中文的 JSON 文本。对其原始 UTF-8 编码可复算 `used_bytes` 与 SHA-256。若自行格式化 JSON，字节数和哈希会改变。选择角色和省略原因另存为不可变记录，不属于文档内容哈希。

## 时点、来源与失效

目标故事时点遵循 [故事状态约定](story-states.md)。指定时点后，有结构化区间的记忆须覆盖该时点；必需记忆不匹配则阻断，可选记忆不匹配则省略。时点留空表示不做故事时间筛选。没有结构化时间的文字记忆可由用户明确选择，平台不猜测适用时间，也不把它补成时间线事实。

正文版本不是当前版本时阻断。所选正式记忆仍为现行版本，但其来源被编辑：必需项阻断，可选项省略。创建时采用作品锁及所有相关资产的统一排序锁集，避免读取一半新、一半旧的来源；审批也使用作品锁，来源编辑使用资产锁。

快照保存后，复查覆盖输入正文、实际纳入的记忆现行指针及其来源版本。不纳入的可选项后来变化，不使已冻结的文档失效；新增但未选择的其他正式记忆也不在该依赖检查范围内。这是明确引用的版本检查，不是完整影响分析、自动召回或语义矛盾检查。

| 原因 | 处理含义 |
| --- | --- |
| `INPUT_CHANGED` | 输入正文已有新版本，核对后另建快照 |
| `SOURCE_CHANGED` | 所选记忆来源已有新版本，先复查记忆来源 |
| `MEMORY_CHANGED` | 已纳入的正式记忆已被替代，选择新批准版本 |
| `STORY_TIME_MISMATCH` | 记忆区间不覆盖目标故事时点 |
| `REQUIRED_CAPACITY_EXCEEDED` | 完整必需内容大于上限，缩小任务范围或调整容量 |
| `OPTIONAL_CAPACITY_EXCEEDED` | 当前剩余容量无法完整容纳该可选条目 |
| `REQUIRED_CONTEXT_BLOCKED` | 必需内容已阻断，因此未尝试组装此可选条目 |

复查只代表检查时点的观察，没有生成执行租约，也不锁住后续编辑。已绑定的任务消费者在领取、发送登记及回报等边界重新校验；复查通过不授予公网外发权限。

## API

前缀 `/api/v1/works/{work_id}/contexts`。用户登录会话可访问，写操作要求 CSRF 与合法来源；Agent 令牌无权读写。

| 方法与路径 | 功能 |
| --- | --- |
| `POST /` | 保存快照，返回 id；保存的记录可能为 READY 或 BLOCKED |
| `GET /` | 按创建时间倒序分页，默认 20、最多 100；不返回完整文档 |
| `GET /{id}` | 固定文档、引用选择、保存时容量与原因，加本次读取的依据状态 |
| `POST /{id}/check` | 在锁下复查并审计，返回 fresh、issues、checked_at、assembly_ready |

上表 `/` 指前缀本身，不增加尾斜线。创建示例：

```json
{
  "title": "第十章分析上下文",
  "objective": "核对人物身份与行踪",
  "input_revision_id": "已保存正文版本ID",
  "story_at": 25,
  "capacity_bytes": 65536,
  "memories": [
    {"proposal_id": "当前批准提案ID", "required": true}
  ],
  "request_key": "调用方唯一标识"
}
```

名称最多 256 字符，目标最多 4000 字符；故事时点、容量要求严格整数，必需标记要求布尔值，重复提案 ID 拒绝。选择顺序影响可选项优先级，属于幂等内容指纹的一部分。改配置不能复用旧请求标识。来源与记忆文字均作为数据保存，不执行为指令、不赋予平台权限。

## 迁移与剩余工作

升级前停止 API／Worker，备份独立平台库并按 [部署指南](platform-setup.md) 显式升级。`0013_context_snapshots` 只新增快照与记忆选择表、索引及不可变保护，不修改旧任务、正文、记忆、账本，也不为旧任务自动生成快照。不支持破坏性降级，需回退时恢复升级前备份。
