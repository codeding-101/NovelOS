# 作品预算与未知费用对账

适用版本：M3 预算基础工作包，schema `0005_work_budgets`。

## 网站使用

登录后从控制台进入“预算中心”，选择作品，设置费用和 token 累计上限。币种支持 CNY 或 USD，首次保存后固定，不做汇率转换。金额最多六位小数；例如 `12.345678` 会精确保存为 `12345678` 微单位，不使用浮点数扣账。

预算按作品全生命周期累计，不自动按月重置。未配置时不允许外部调用；费用或 token 上限为零意味着相应维度没有可用额度。人工与本地流程校验不消耗此预算，也不会伪装成真实模型消费。配置额度本身不启用外部执行或付费服务。

当前概况列出上限、已结算、预留中与可用额度。保存预算使用版本检查，其他页面或账本已经改变时拒绝覆盖并保留输入；点击“刷新账目”读取最新值，核对后再保存。降低上限不会删除已发生费用或释放未确认调用，界面会显示超额并阻止新的调用登记。

调用列表每页 20 条，可筛选待对账；账本展示最近 20 条不可变事件，完整历史可通过分页 API 查询。

## 调用状态与恢复

| 状态 | 含义与额度行为 |
| --- | --- |
| RESERVED | 已预留，尚未登记发起；暂停、取消或执行过期时可以释放 |
| DISPATCHED | 已登记发起，可能到达供应商；不代表服务端必然收到或已成功 |
| UNKNOWN | 中断后费用不明确；保留全部预留，同时阻止该作品新增外部调用 |
| SETTLED | 有实际费用、输入／输出 token 和回执依据；释放预留并计入实际用量 |
| RELEASED | 确定尚未登记发起的预留已释放，不计实际消费 |

系统先预留再登记发起，实际网络 I/O 必须在数据库提交后执行。登记后进程崩溃、暂停或取消不能证明没有发生费用，所以必须保留 UNKNOWN。当前外部执行仍关闭；以上是已实现并通过隔离故障测试的账本规则，不是已经完成真实供应商联调。

恢复扫描会处理过期执行的预留。存在未知费用的任务不能重新领取或恢复；已取消／失败的任务仍保留独立账目，不能因任务结束而免除待对账责任。人工核对完成不会自动恢复任务或接收旧执行的候选结果。

## 人工核对

对 UNKNOWN 调用点击“核对这笔调用”，依据供应商回执填写实际费用、输入与输出 token、唯一回执标识及核对依据，勾选确认后提交。所有数值均须明确填写；确有未计费证据时可以填写零，未知情况应继续保持待对账。

同一执行者的同一回执只能用于一笔调用，包括跨作品回报。同一预留重复提交完全相同的结算内容会返回原记录，改变已结算内容会被拒绝。对账页面仅处理 UNKNOWN，不允许把未发起的预留手工记成消费。

实际费用超出预留时照实记账，并标记超出预留；若累计费用或 token 超过上限，则阻止新增调用，直到用户核对并调整额度。不会截断实际费用或隐瞒超支。当前还没有账单撤销／冲正功能，已结算记录不提供编辑入口。

## API 与内部适配约定

接口前缀 `/api/v1/works/{work_id}/budget`，沿用登录、CSRF 和来源保护：

| 方法与路径 | 功能 |
| --- | --- |
| `GET /` | 是否配置、固定币种、版本、两类额度、超额和待对账数量 |
| `PUT /` | 设置累计上限；首次 `expected_version=0`，之后使用当前版本 |
| `GET /reservations?offset=0&limit=50&unknown_only=false` | 分页调用记录，单页最多 100 |
| `GET /events?offset=0&limit=50` | 分页不可变账本，单页最多 100 |
| `POST /reservations/{id}/reconcile` | 携带预留版本、实际费用和用量、回执及依据进行人工对账 |

上表 `/` 表示前缀本身，不需要额外尾斜线。金额字段为 `*_microunits`，每一币种单位等于 1,000,000 微单位。金额和用量只接受非负整数，不接受浮点数、字符串或布尔值；单次字段上限为 `10^12`。预留 token 必须大于零，免费调用也须受 token 上限约束。

预留、登记发起和自动结算是 `budget_service` 内部事务接口，没有开放公共写入路由。调用者必须先锁任务，再锁作品预算；预留绑定有效的 task／attempt／executor，只允许未来付费 API／Agent 模式，人工、本地校验和 `offline_v1` Agent 被拒绝。

适配器必须在网络请求前提交预留与 DISPATCHED，只有首次登记返回 `True` 才能发送；不得在重复登记返回 `False` 时重复调用。预留使用 `(attempt_id, operation_key)` 去重，结算使用 `(executor_id, receipt_key)` 去重。状态、余额、账本和审计在同一事务内提交，失败整体回滚。适配器需要提供保守的费用／token 上界；本工作包尚未包含模型价格计算和供应商用量解析。

## 当前边界与验收

网站可管理真实的用户预算设置，但当前没有真实调用来源。浏览器验收中的费用来自明确标记的隔离账本样例，不是供应商账单。SQLite 和 PostgreSQL 用例验证并发预留、去重、异常回滚、跨作品回执冲突、未知费用、超支、不可变事件以及保留既有任务的升级。

当前已提供 [执行者路由与外部配置预算检查](executor-routing.md)，检查不预留费用，不授权实际发送。[离线 Agent 网关](agent-gateway.md) 仅接收零供应商用量，不代表免费模型额度管理。[任务累计预算](task-budgets.md) 已实现，模型任务须同时满足任务与作品两层限制；任务上限不会预先独占作品余额。真实 API／付费 Agent 适配、供应商账单拉取及供应商月度免费额度管理仍未实现。朱雀每月额度需在 M8 按真实计量与周期规则实现；作品累计 token 上限不能替代朱雀免费额度，更不能作为检测通过证据。定稿门禁仍保持关闭。

阶段证据见 [执行记录](../planning/execution-status.md)，决策见 [ADR 0005](../decisions/0005-work-budgets.md)。

M3 后续已增加 [本机模型协议联调](model-api-rehearsal.md)：按冻结声明价格及整个上下文额度预留，解析模拟响应的 token，与候选保存原子结算。测试中可以验证真实账本事务，但响应和费用都来自明确标识的本机模拟服务，不代表已获得供应商账单或授权公网消费。
