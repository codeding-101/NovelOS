# 模型 API 配置与本机协议验收

适用版本：schema `0008_model_api`。本工作包完成 Chat Completions 文本协议、预算预留、用量解析与候选保存的本机联调，**未开放公网模型调用或真实付费执行**。

## 配置入口

在“执行者与路由设置”登记模型 API，勾选“登记 Chat Completions 配置”，填写：

- 完整接口地址，路径以 `/chat/completions` 结束；正式配置只接受不含 URL 凭证、查询参数或片段的公网 HTTPS 地址。
- 模型标识、最大输出 token（1—32768）和请求超时（1—30 秒）。
- 模型 API 类型凭证引用、上下文上限、币种及输入／输出价格。上下文上限必须大于最大输出。

保存配置不会发起连通性测试或真实请求。公网配置始终显示 `MODEL_API_DISABLED`，不能创建可执行模型任务；`development` 与 `production` 的 Worker 不运行模型适配器。没有可通过环境变量打开公网调用的开关。

仅 `NOVELOS_ENV=test` 且地址为字面量 `http://127.0.0.1:<端口>/…/chat/completions` 或 IPv6 回环时，才允许本机模拟流程。传输层再次检查此限制，拒绝公网、域名、重定向与环境代理。测试环境须使用独立库和一次性假凭证，不要把生产数据库改为测试环境。

在隔离测试环境，把执行者加入作品允许列表并配置模拟预算后，可以创建模型任务。Worker 自动领取；任务中心展示明确标注的模拟候选与 token 用量，预算中心显示模拟调用与账本。保存正文和定稿状态不会因此改变。

## 请求与费用边界

每个任务尝试只发送一个文本、非流式请求，参数为 `model`、两条 `messages`、`stream=false`、`n=1` 和 `max_completion_tokens`。输入包含任务类型、目标、标题与所选正文版本，不读取其他作品或资料。不发送工具定义，不执行返回的工具调用，不自动重试供应商请求。

字段与响应形状按 [OpenAI 官方 Chat Completions 文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) 核对。此处只实现该协议的受限子集，不表示任意“兼容”服务都可直接接入，也未选定任何真实模型或价格。

创建任务时保存不可变的地址、模型、凭证引用、价格、上下文与输出上限。领取和发送前重新检查；这些配置变更后旧排队任务被阻止，应使用新配置新建任务，或恢复原配置再继续。启用、能力、可用性和作品规则仍按当前规则检查。

预留不使用“字数除以某个系数”的乐观估计：为 `上下文上限 − 最大输出` 预留输入 token，为最大输出预留输出 token；总预留为声明的整个上下文额度。两个方向的费用分别按整数微单位向上取整。完整消息 UTF-8 字节数加 512 的结构余量仅作为输入容量的保守筛选，不是对所有分词器的数学保证；真实发布前仍须验证供应商分词、上下文限制和计费规则。

预算不足、存在未知费用、凭证缺失、输入过大或冻结配置不匹配时，阻止发送。预留和 `DISPATCHED` 同事务提交后才能发送；同调用标识再次登记不重复发送。故障发生在登记之后但请求之前，也按可能已发生费用处理，不能推断为免费。

响应用量要求 `prompt_tokens`、`completion_tokens`、`total_tokens` 为非负整数，且总数等于两者之和；缺失、布尔值、负数或矛盾数据不按零费用处理。不支持图像、音频、缓存写入附加计费或非默认服务层级；缓存读取不打折，按声明输入价计算。回执使用响应标识的哈希去重，不将供应商错误正文或凭证写入日志。

结算金额是“上报 token × 冻结声明价格”的模拟账本值，不是实际账单或未来供应商费用保证。上报用量超过声明容量时照实记录，并将候选设为不完整、暂停任务。

## 故障与恢复

| 场景 | 处理 |
| --- | --- |
| 完整 `stop`、非空文本、有效用量 | 同一事务结算并保存候选，原文不变 |
| `length`、空文本、工具调用或不支持的结果形状 | 有效用量仍结算，候选为 PARTIAL，任务暂停 |
| 超时、非 200、重定向、响应过大、缺失／不可信用量 | 调用转 UNKNOWN，保留预算占用，暂停并等待对账，不自动重发 |
| 已登记发送后 Worker 中断 | 租约过期恢复为未知费用暂停；不能因未收到响应就释放占用 |
| 调用途中取消／暂停 | 迟到的有效用量仍可入账，候选隔离，不能把任务改回成功 |
| 结算后保存候选失败 | 两项同事务回滚，调用保留为待对账，不能出现半次成功 |

响应未成功持久化或用量无法解析时，不保存有效候选；恢复需要核对调用，可能需要新任务。平台不承诺追回未落库的供应商响应。人工对账不会自动恢复任务，未知费用仍按 [预算指南](work-budgets.md) 处理。

## 验收与后续

`scripts/model_fixture.py` 仅监听本机临时端口，返回标注为模拟的固定文本，不调用模型。`scripts/platform_smoke.py` 在临时库验证网页配置、Worker、候选及预算展示；`backend/tests/test_platform_models.py` 覆盖双库并发、事务回滚和故障。执行方法见 [部署指南](platform-setup.md)。

开放真实调用仍需确认正文外发与预算内消费授权，并实现公网目标限制、TLS／DNS 与网络边界、供应商实际计量及有限真实联调。当前 M3、M1 容器部署验收和后续朱雀门禁均未整体完成。参见 [执行记录](../planning/execution-status.md) 与 [ADR 0008](../decisions/0008-model-api-rehearsal.md)。
