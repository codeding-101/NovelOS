# 作品、草稿与历史版本

当前范围：M2 作品资产管理，个人预览。新平台不自动导入旧 SQLite 数据库，不授予定稿状态。

## 开始使用

1. 按 [部署与开发指南](platform-setup.md) 配置并升级独立平台库，登录控制台。
2. 点击“进入作品空间”，创建或选择作品。
3. 在目录添加卷、章节、场景或资料。章节可以不分卷；场景必须属于本作品的一章。
4. 选择资产编辑标题和正文。“保存新版本”创建一份独立快照，旧稿保留。

登录失效时，编辑器保留当前输入。使用提示中的链接在新标签页登录，回到编辑器重新连接后再保存。浏览器关闭不会自动保存输入；页面会对未保存内容提示离开确认。当前没有自动保存或断网草稿存储。

## 比较、冲突与恢复

点击历史版本可以查看历史正文，并比较它与当前已读取的已保存版本。未保存的输入不参与版本差异。差异预览合计最多支持 20 万字符和 5000 行，超过时仍可读取历史正文。

“将此版本恢复为新版本”会创建新的版本号，记录来源版本，不删除中间的修改。恢复包括标题和正文，当前尚不涉及未来的 CANON 或记忆状态。

两个页面从同一版本编辑时，只有先提交的一个会成功；另一个显示冲突并保留输入。先将要保留的输入复制到安全位置，再点击“读取最新版本”查看已保存正文，合并后保存。不会自动将陈旧输入覆盖到新版本上。

## 导入与导出

- 支持 UTF-8 编码的 `.txt` 与 `.md`，单文件最多 2 MiB；一次导入为一章或一份资料，不自动切章。
- 原始文件字节、文件名及 SHA-256 单独保存；BOM、CRLF、空格和尾部换行不会在导入时规范化。
- 不支持的编码、含 NUL 的文本、路径式文件名或超限文件会被拒绝，不会留下半个导入资产。
- “导出草稿与历史”生成 ZIP：`manifest.json`、各资产的历史正文和元数据、导入时保存的原始文件。目录使用生成的资产标识，不使用用户标题拼接路径。
- 清单逐项包含哈希和字节数，原文件项同时注明原文件名及对应版本。所有内容明确为 `DRAFT`，`finalization=false`。正文文件本身不插入标记，以保持原文哈希。
- 导出捕获当时的资产和版本号，只包含已提交的版本；导出期间新增的版本留待下次导出。
- 当前单次导出限原始数据合计 100 MiB、10000 个文件；超限会明确失败，不交付截断的 ZIP。

草稿导出包用于文本及版本查验，尚无 ZIP 恢复导入器，不能替代数据库及加密主密钥备份。格式版本 2 还包含附件原文件、版本引用和旧库来源映射。附件即使尚未同步到文件目录，也可以从数据库下载和导出。

## 附件、检索与引用

作品空间底部可上传任意类型的原始附件，单个最多 4 MiB，选择归属于整部作品或某个资产。文件只按原字节保存，以下载方式返回，不执行或自动解析 HTML、PDF、Office 等内容。当前附件和历史引用为保留式记录，不提供覆盖／删除操作。

搜索按标题和正文进行文字包含匹配，支持中文，只检索各资产当前版本；不提供语义检索。页面显示已完成索引的资产数量，尚未处理的版本暂不出现在搜索结果中。定稿和正式记忆权限不会因能搜索到草稿而改变。

“版本引用与依赖”将双方当时的已保存版本绑定。任何一方产生新版本，原绑定仍保留，列表会提示复查；不会把旧绑定自动转到新正文，也不会宣称它覆盖所有剧情因果。新版本可以另建引用，历史绑定保留用于查验。

## 后台同步与恢复

正文、原稿及附件保存时，同一事务写入待处理任务。Worker 生成按 SHA-256 定位的文件副本和可重建检索表。数据库是权威来源；文件缺失或索引故障不会导致正文保存失效。

启动 `python -m app.platform.worker` 持续处理队列。文件目录由 `NOVELOS_STORAGE_ROOT` 指定，本地默认 `data/platform/files`；Compose 中 Worker 使用命名卷 `platform-files` 的 `/data/projections`。

每次领取任务有 60 秒期限；失败自动退避，最多尝试 5 次，之后显示失败并停止。后台退出或异常后重新启动，可回收过期任务；旧领取结果不能替代新领取者提交。解决目录不可写、磁盘不足等问题后，页面可重试失败项，或点击“重建索引与文件副本”。重建不会删除原文。文件目录不是独立的完整备份。

也可在已配置目标平台库的 `backend` 目录执行：

```powershell
.\.venv\Scripts\python.exe -m app.platform.cli rebuild-projections <作品ID>
.\.venv\Scripts\python.exe -m app.platform.cli process-projections --limit 100
```

使用 Compose 时，处理命令应在 `worker` 容器内运行，使它使用同一文件卷。`process-projections` 是有界批次，返回处理过的数量；任务成功与否请查看页面状态。AI 创作任务及 API 费用调度尚未开放。

## 旧 SQLite 显式导入

先保留旧库备份及新平台库备份。指向新平台库的配置不变，传入明确的旧库副本路径及稳定来源标识：

```powershell
cd backend
.\.venv\Scripts\python.exe -m app.platform.cli inspect-legacy <旧库副本路径>
.\.venv\Scripts\python.exe -m app.platform.cli import-legacy <旧库副本路径> --source-id my-original-library
```

导入一次性创建独立新作品，原库以只读事务打开；不会读取或修改旧记录中的 `content_path`、`source_path` 所指向的文件。外部文件若需进入新平台，应显式上传，旧目录与备份继续保留。

章节转为 `DRAFT` 版本；作品元数据、人物／人物状态／关系、CANON 事实、事件、时间线、伏笔、世界规则、章节计划、承诺、文风档案、灵感碎片作为原始来源记录保留。旧 CANON／COMPLETED 不自动获得新平台的正式权限。在“旧库来源记录”中可查看原始字段，导出包含这些字段和新旧标识映射。

旧派生索引、嵌入、执行与审查报告等未迁入运行模型，命令输出 `skipped_tables`；原库保留这些内容。导入上限为受支持记录合计 100 MiB 或 100000 条，单章仍受 2 MiB 文本上限约束。遇到孤立记录、校验或提交错误，整个目标事务回滚。

同一 `--source-id` 和相同受支持数据再次导入时复用已提交映射，即使旧文件换了路径，也不会覆盖后来编辑的新稿。同一来源的受支持数据已变化时返回 `SOURCE_CHANGED_REVIEW_REQUIRED`，需核对后另行安排增量迁移；不要为绕过这一检查随意改来源标识。

可先在仓库根目录做完全隔离的演练：

```powershell
.\backend\.venv\Scripts\python.exe scripts\legacy_import_rehearsal.py <旧库副本路径>
```

演练只生成临时新库，校验章节、重复导入、后台同步和导出，结束后清理临时新库；摘要报告保存在忽略目录 `data/validation/legacy-import-rehearsal.json`。

## 升级已有 M1 库

停止 API／Worker，保留独立平台库备份与主密钥，使用相同配置运行：

```powershell
cd backend
.\.venv\Scripts\python.exe -m app.platform.cli upgrade
.\.venv\Scripts\python.exe -m app.platform.cli check
```

最新迁移为 `0003_asset_delivery`，它会为已有正文版本及原稿补建后台同步任务。API 只检查迁移版本，不在启动时改表；账户、会话与加密凭证表不因本次升级重建。原 `data/novelos.db` 仍保持隔离。
