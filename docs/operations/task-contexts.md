# 任务绑定上下文与执行校验

适用版本：schema `0014_task_contexts`。已组装的上下文快照可以在创建任务时绑定，覆盖人工、本地流程校验、离线 Agent 和仅测试环境的本机模型协议。真实模型调用、外部消费和正文定稿仍关闭。

## 网站流程

1. 在 [上下文页面](context-snapshots.md) 保存 READY 且依据未变化的快照。
2. 在任务中心选择作品和“绑定上下文快照”。系统核对当前状态，再填入快照的正文和任务目标；绑定期间这两项不能编辑。修改它们须先取消选择，或另建快照。
3. 选择执行者及任务类型、尝试次数、依赖和适用预算，创建任务。快照的目标与输入须匹配；阻断、过期依据、跨作品和不匹配的快照会拒绝创建，配置输入保留。
4. 任务详情展示固定快照标识、哈希及当前依据状态。领取人工任务后可展开完整文档；网页提交候选时自动附带本次领取的快照确认信息。

绑定只在任务创建时确定，没有换绑、解绑或覆盖入口。任务过期后，保留旧任务、检查点、候选和账目，用新快照新建任务。没有选择快照时继续原有正文任务流程；旧任务不会自动补绑定。

## 校验与失效行为

| 边界 | 行为 |
| --- | --- |
| 创建 | 核对作品、正文版本、目标、READY 状态和所有纳入依据；路由与容量计算包含完整快照 |
| 领取 | 重新核对绑定依据；失效则 FAILED／CONTEXT_STALE，不新增 attempt |
| Agent 重连、人工接续 | 依据失效时拒绝发放新的执行令牌 |
| 心跳、新检查点 | 依据失效时拒绝续期或保存新进度，既有内容保留；运行状态可等待后续回报或原租约到期处理 |
| 暂停后恢复 | 旧快照失效则拒绝恢复，不能以调额或重试换用新设定 |
| 本机模型发送登记 | 在预留、发送登记之前重新核对；未通过不产生新调用预留或请求 |
| 新结果回报 | 再查依据及快照确认。依据失效或确认不匹配时保存 QUARANTINED，任务 FAILED；产物保留供复查 |

同一已保存检查点、结果或创建请求的幂等重试仍返回原回执，不能用它回退状态或授权新的工作。已经完成的候选后来出现依据变化时，详情会显示变化；本版不追溯删除或重写已接收候选，后续影响处理仍属 M7。

输入正文和纳入记忆／来源是固定依赖范围，未选择的新事实及已省略项不纳入校验。快照确认只说明客户端返回了指定标识与哈希，不能证明模型正确理解、遵守设定或生成了高质量内容。

绑定任务采用 task → work → executor／quota／budget → asset 的适用锁顺序。创建时先锁作品，路由后统一锁资产复查，再一次保存任务、绑定、路由记录与审计。来源写入与记忆替代使用同一资产／作品锁；检查与网络请求分开，网络期间不持有数据库长事务。登记发送之后仍可能有新编辑，回报时的第二次校验负责隔离过期产物，不承诺撤回已经送出的请求。

模拟调用已经产生用量，而回报时依据失效：先按模拟响应结算测试账本，再同事务隔离产物；不因内容过期丢账，不重复结算。未知用量仍沿用既有 UNKNOWN 与对账规则。

## 协议与接入

创建接口 `POST /api/v1/tasks` 增加可选 `context_snapshot_id`。正文仍使用 `input_revision_id`，任务目标仍使用 `objective`，二者须匹配快照；目标只允许现有任务输入规则下的首尾空白归一。任务详情新增只读 `context` 摘要，绑定由不可变表存储。

未绑定任务继续 TaskEnvelope／ResultEnvelope `1.0`，领取响应不额外插入空 context 字段，旧创建哈希及结果幂等保持兼容。

绑定任务的领取、接续和 Agent 重连返回 TaskEnvelope `1.1`，增加：

```json
{
  "context": {
    "snapshot_id": "固定快照ID",
    "sha256": "64位小写十六进制文档哈希",
    "document": "原始序列化快照文档"
  }
}
```

结果须使用 ResultEnvelope `1.1` 并携带：

```json
{
  "protocol_version": "1.1",
  "context_ack": {
    "snapshot_id": "固定快照ID",
    "sha256": "原始文档哈希"
  }
}
```

未绑定任务使用 1.0 且不携带确认。缺失确认、错误 ID／哈希或协议不匹配不会被静默接收，合法格式但不匹配的回报以 `CONTEXT_MISMATCH` 隔离；非法字段格式先按 schema 拒绝。`evidence_revision_ids` 仍按既有契约引用主输入版本，快照记忆的完整来源从固定快照追溯。

任务专属 Agent 令牌只获得其任务中的快照，不获得用户上下文库、作品库或审核权限。接入方应支持 1.1 后再领取绑定任务，旧客户端不能省略确认直接完成它。参考离线客户端会核对文档哈希，将哈希纳入诊断检查点，并持久化含确认的回报以恢复丢失回执；它仍只是确定性协议诊断工具。

本机模型适配器将数据库固定的完整快照作为用户材料发送，未增加工具或系统权限。路由容量检查使用包含快照的完整消息，保留原有字节代理及输出预留限制；没有真实分词保证。人工网页、本地诊断和本机模型适配器自动构造确认，不能绕过服务端再校验。

## 迁移与边界

按 [部署指南](platform-setup.md) 停 API／Worker、备份平台库再显式升级。迁移只新增 `task_contexts`、索引和不可变触发器；不修改历史任务、快照、正文或调用账本。旧任务保持未绑定，不提供破坏性降级。

分层摘要、自动召回与中文检索评估、提供者真实分词、重大变更审批和统一正式提交仍待后续。此工作包不代表完整 M4／内部 Alpha 或真实供应商集成完成。设计见 [ADR 0014](../decisions/0014-task-contexts.md)。
