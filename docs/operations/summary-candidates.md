# 分层摘要候选与来源管理

适用 schema：`0015_summary_candidates`。本工作包交付用户 API，不包含网页、自动生成、摘要审核或上下文接入。内容由用户提交；平台验证引用及结构，不验证概述的语义真实性。摘要始终为 CANDIDATE，不进入正式记忆检索，不自动成为剧情事实。

## 创建与查询

已登录用户使用 `POST /api/v1/works/{work_id}/summaries`，提交会话要求的 CSRF 与 Origin。Agent 任务令牌不能调用用户接口。

```json
{
  "level": "chapter",
  "title": "第一章摘要候选",
  "content": "角色观察到的事件概述。",
  "narrative_notes": "采用限知视角；不要把角色的怀疑写成已确认事实。",
  "unresolved": "船上人物的身份尚未揭示。",
  "source_revision_ids": ["同作品当前正文版本ID"],
  "child_summary_ids": [],
  "request_key": "唯一提交标识"
}
```

- 层级为 `scene`、`chapter`、`volume`、`book`。可以直接依据原文提交任一层级；若引用下级摘要，只允许紧邻下一层，不允许同层或跳层。不能引用尚不存在的摘要，所以不能形成循环。
- 每次最多 20 个直接原文来源和 20 个下级摘要；至少存在一种来源。下级摘要的原文来源递归展平、去重后继承，上限 200 个版本，超限拒绝，不截断。
- 概述最多 32,768 字符，叙事备注与未决信息各最多 16,384 字符；这三个文本字段不自动解释或抽取事实。未填写备注不表示没有悬念或认知限制。
- `GET /summaries?offset=0&limit=20` 查看候选历史；`GET /summaries/{id}` 查看来源、下级引用及新鲜度。列表最多每页 100 条。

响应的 `document` 是结构化文档，`document_text` 是原始序列化文档；`sha256` 对后者的 UTF-8 字节计算。文档冻结直接来源、展平来源的版本／哈希和下级摘要 ID／哈希，保留完整输入。`source_changed` 与 `changed_revision_ids` 是读取时状态，不进入原始文档或哈希。

## 失效、幂等与恢复

创建时先锁作品，再按现有来源服务的资产排序锁定全部原文依据；任何来源已不是当前版本即拒绝，包括下级摘要继承的来源。审计和摘要在同事务中保存，失败整体回滚。

原文更新后，已有摘要及所有引用它的上级摘要保留，但因继承来源变化而标记需复查；不能继续用失效下级摘要创建上级。没有自动重写或现行摘要指针，重新概述须创建新候选，并在新上级中显式引用它。已有上级不会悄悄换用新候选。仅改写某份摘要并不会宣告其他历史候选过期；当前失效判断针对原文版本。

同作品同请求键、相同内容重试返回原 ID，即使原文随后变化；同键不同内容返回 409。读取旧回执不表示依据仍有效。数据库触发器禁止更新和删除摘要记录。文档内引用由创建服务校验，引用对象不可变；JSON 内部引用未单独建立数据库外键。

迁移只新增摘要候选表、索引和触发器，不为旧作品或任务补造摘要。正式部署应先备份、停 API／Worker，再按 [部署指南](platform-setup.md) 显式升级；不支持破坏性降级。本轮验收只迁移隔离测试库。

## 后续边界

下一工作包继续摘要审核、候选替代与网站入口，之后才接入上下文及执行者任务。叙事备注借鉴结构化叙事分析，但没有实现自动识别限知视角、角色认知或语义矛盾。检测分数、文学质量与摘要保真继续分开处理；真实模型调用及正文定稿仍关闭。
