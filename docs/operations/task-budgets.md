# 任务累计预算

适用版本：schema `0009_task_budgets`。真实模型调用继续关闭；以下执行验证使用隔离数据库和本机模拟服务。

## 设置与恢复

模型任务拥有独立的累计费用和 token 上限，覆盖同一任务的所有尝试。创建时可以同时填写两个上限；留空时按冻结调用计划的单次预留乘以最大尝试次数设置，单项最大为 `10^12`。自定义额度必须至少容纳一次计划预留，币种必须与调用计划一致。人工、本地校验和离线 Agent 不使用此额度。

任务详情显示累计已结算、占用、剩余额度和待对账数量。任务预算与作品预算同时生效：提高任务上限不会提高作品上限，也不会给任务预先独占作品额度。实际预留仍须通过作品预算检查。

额度不足时，领取会暂停为 `TASK_BUDGET_EXCEEDED`，不消耗一次尝试；恢复、预留和登记发送也会重新检查。未结束的模型任务可以调整额度，保存后仍须手动恢复暂停任务。次数、期限、输入版本和其他执行条件仍然有效。

保存使用任务版本检查。其他页面或任务状态已经变化时，服务器拒绝覆盖并保留当前输入；点击“载入最新任务预算”读取最新值后重新核对。任务自动刷新不会覆盖正在编辑的额度。

## 记账规则

已结算调用按实际金额及输入、输出 token 累计；`RESERVED`、`DISPATCHED` 和 `UNKNOWN` 按预留累计占用；`RELEASED` 不计消费。重试和暂停恢复不会重置累计值。

降低上限可以使任务显示超额，但不会删除账目、撤回已发送请求或释放未知费用。未发送的预留在暂停／取消时释放；可能已发送的调用继续按 [未知费用对账规则](work-budgets.md) 处理。实际用量超过上限时仍照实结算，后续调用被阻止，不截断账目来制造合规余额。

## 接口与升级

- `POST /api/v1/tasks` 可传入 `spending_limit`：`currency`、`limit_microunits`、`limit_tokens`。不传或为 null 时采用默认额度；重复创建不会覆盖后来调整的预算。
- `GET /api/v1/tasks/{id}` 返回 `spending_budget`，包含是否支持／配置、币种、两类上限、累计已结算／占用／剩余、未知数量及超额标志。
- `PUT /api/v1/tasks/{id}/budget` 接收 `expected_version` 及上述三个额度字段。沿用用户登录、CSRF 和来源保护，Agent 令牌不能调用此接口。金额以百万分之一币种单位表示；两类上限只接受 `0` 至 `10^12` 的整数，布尔值不接受。

升级前停 API／Worker 并备份独立平台库，按 [部署指南](platform-setup.md) 显式迁移。迁移新增三个可空字段，不为历史任务补造授权额度，也不修改历史调用。旧模型任务必须先配置任务预算才能继续；旧创建请求的幂等键仍可返回原任务。迁移不提供破坏性降级。

后续 schema `0010_monthly_quotas` 已提供 [共享月度 token 配额](monthly-quotas.md)，已绑定执行者须同时满足任务、作品及共享配额限制。供应商实际免费额度及真实账单仍未接入；任务累计 token 不代表朱雀剩余额度或检测结果。用户已明确要求继续开发、暂不开放真实调用，后续独立工作包沿用这一边界。
