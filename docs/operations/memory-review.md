# 记忆提案与人工审核

适用版本：schema `0011_memory_review`。这是 M4 可离线交付的记忆与审核基础；真实调用继续关闭，正文仍为草稿。

## 网站流程

从控制台进入“记忆与审核”，选择作品。记忆暂以带来源的文字条目保存，类型包括人物、关系、世界规则、事件、伏笔和承诺。

1. 填写稳定的记忆标识、标题和内容，选择 1 至 20 个当前来源版本。例如同一人物的身份条目使用“人物-林舟-身份”，不同条目使用不同标识。
2. 可关联同作品已接收的任务候选 ID；来源必须包含该任务的输入版本。关联只记录来源，不代表系统验证了事实，也不会自动批准。
3. 提交后进入“待审核”，不出现在正式记忆及其检索中。提案保存后不可编辑；需要修改时另建提案。
4. 查看提案内容、修改前内容和来源原文，填写审核说明，勾选核对确认后点击“批准并生效”；不采纳时可填写理由驳回。
5. 批准后建立或更新该标识的正式版本。修改已有条目须从正式记忆点击“提出修改”，新的提案绑定当前版本，原正式记忆继续有效，直到新提案获批。

当前所有变更都需用户审核，不自动判定重大／普通变更。用户会话可以提交与审核；外部 Agent 令牌无权访问这些接口，现阶段由用户转交候选，不直接扩展 Agent 网关权限。

尚无正文来源的新设定，可先在作品空间保存为资料资产，再把该版本选为来源；这表示用户提供的设定依据，不要求伪造正文证据。

## 失效、并发与历史

网站提案有效期为 7 天，API 可指定 60 秒至 7 天；有效期只限制未决定提案的批准，已批准的记忆不会在 7 天后自动消失。

批准前同时检查来源仍为当前资产版本、同一标识的正式记忆仍为提案所依据版本，以及提案未过期。任一不满足均拒绝批准。刷新提案状态可查看原因；旧提案仍可驳回，不可通过重试覆盖新事实。失效、驳回或修改后的内容必须新建提案并重新核对。

同一提案重交相同审核决定和理由返回原结果；改变已保存的决定或理由返回冲突。重复提交旧批准不会把正式记忆回退到旧版。两个提案竞争同一正式版本时只有一个能够生效，另一个标记依据已变化；浏览器冲突保留尚未提交的输入。

提案、来源绑定和决定均不可修改或删除。版本历史按批准顺序保存，网站显示最近 100 个已批准版本，API 可分页查看。恢复历史内容须以当前正式版本为基础另提修改，不能覆盖或删除已有历史。审批、正式指针和审计在同一事务提交，失败全部回滚。

已批准记忆的来源后来被编辑时，页面显示“来源已有新版本，需复查”，保留既有批准和旧来源证据，不自动撤销或重写记忆。这不是完整语义影响分析；相关报告失效、剧情连锁修复和关联回滚仍属后续阶段。

## API

前缀 `/api/v1/works/{work_id}/memory`，所有接口要求登录，写请求需要 CSRF 和合法来源。

| 方法与路径 | 功能 |
| --- | --- |
| `GET /` | 只查询现行正式记忆；支持 q 字面子串、kind、offset、limit |
| `GET /proposals` | 按 pending／approved／rejected／all 列出提案，默认 pending，支持分页 |
| `POST /proposals` | 提交不可变候选，按作品与 request_key 幂等 |
| `GET /proposals/{id}` | 提案、来源哈希与版本、失效原因、审核说明及当前状态 |
| `POST /proposals/{id}/decision` | outcome 为 approved 或 rejected，reason 必填 |
| `GET /history?entry_key=…` | 指定标识的已批准版本，按版本降序分页 |

上表 `/` 表示前缀本身，无额外尾斜线。每页最多 100；提案正文最多 32768 字符，来源最多 20 个且不能重复。新建提案的 `base_proposal_id` 为 null，修改必须传当前正式提案 ID。`source_revision_ids` 必须属于同一作品且为当前资产版本；`submission_id` 可空，仅接受同作品 ACCEPTED 候选，并要求包含其输入版本。`ttl_seconds` 仅接受整数。

候选文字不执行为指令，来源中出现的要求不改变平台权限。检索目前为字面子串，不是语义检索或一致性证明。

## 迁移和完成边界

升级前停 API／Worker 并备份独立平台库，按 [部署指南](platform-setup.md) 显式升级。迁移只新增记忆表；旧正文、任务结果、旧版 CANON 或 `COMPLETED` 不会自动变成新平台正式记忆，也不获得定稿状态。迁移不提供破坏性降级。

当前未实现故事时间线的结构化状态、倒叙／插叙时点查询、自动抽取、上下文装配、审批分类和批量正式提交。正式记忆批准不会修改正文、定稿或朱雀门禁，不会触发模型调用。M3 真实联调、完整 M4 和内部 Alpha 退出标准仍待完成。
