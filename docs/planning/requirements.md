# NovelOS 需求规格

版本：规划基线 1.0

日期：2026-10-23

状态：根据用户已明确需求整理；技术机制详见架构方案。

## 1. 产品定位与成功标准

NovelOS 是面向长篇小说的运行环境、控制平台与工作流程操作系统。平台组织、约束、记录、检查和恢复创作过程，创作、分析、研究、审查和修改由用户接入的模型 API、外部 Agent 或用户完成。

成功标准：一部百万字级作品可以持续创作；换模型或 Agent 后仍保留作品资产、规则与进度；自动任务的成本和权限有边界；任何正式内容变更都能查明来源、比较版本并恢复；中断后能从检查点继续。

用户以 AI 创作为主，提供作品方向、资料、反馈和必要决策。系统按明确规则自动推进，对不确定事项给出依据、选项与影响，等待用户处理。

本轮建设不包含自研或训练小说生成模型、多租户商业 SaaS、多人实时协同编辑、自动操作小说平台投稿后台。多作品管理属于个人使用范围。平台专属发布检查、Obsidian 和读者数据等旧有功能作为可选扩展评估，不挤占核心闭环。

## 2. 角色与对象

| 角色 | 职责与边界 |
| --- | --- |
| 用户 | 提供方向与资料，配置执行者和预算，处理审批，编辑和恢复资产 |
| 模型 API 执行者 | 在已授权上下文内完成生成、分析、审查等任务，返回结构化成果 |
| 外部 Agent | 通过平台协议领取或接受任务，使用授权工具，汇报进度与成果 |
| 用户执行者 | 领取人工任务、补充信息、提交修改；与自动执行结果同样留档 |
| 平台 | 调度任务、构造上下文、控制权限与成本、验证成果、提交正式状态 |

所有 AI 与 Agent 返回内容先成为候选成果。正式资产写入由平台受控提交路径执行，审批或自动规则的授权必须可追溯。执行者无直接数据库、CANON 或服务器管理权限。

## 3. 核心使用流程

### 3.1 建档与创作准备

创建作品 → 设置题材、目标篇幅和创作目标 → 导入资料及旧稿 → 建立世界观、人物与故事规划 → 确认初始正式设定 → 建立文风档案 → 配置执行者、预算与审批规则。

AI 可以协助生成作品规划和设定候选。资料中的建议、外部执行者的推断、学习成果均不能直接变成作品事实。

### 3.2 持续创作

用户发出目标 → 平台拆分卷、章、场景任务与依赖 → 构造版本固定的任务上下文 → 选择执行者 → 生成候选正文 → 抽取候选记忆 → 一致性、文学质量与文风检查 → 朱雀检测 → 在上限内修改与复检 → 必要审批 → 事务性定稿与正式记忆生效 → 创建下一任务。

单章或连续多章运行均受任务数、章节范围、金额、token 和运行时长上限约束。用户可随时请求暂停或取消，并查看已完成工作及在途调用。

### 3.3 不确定与重大变更

遇到事实冲突、多个互斥方案、重大剧情调整、不可估算费用或缺少关键输入时，创建人工决策项。用户可批准、驳回、调整方案或补充信息；回复后继续对应任务。浏览器关闭后决策项仍然存在。

### 3.4 早期设定修改

提出变更 → 生成明确引用和语义推测两类影响报告 → 用户审批 → 新设定版本生效 → 标记相关章节、摘要、上下文和检查报告过期 → 生成修复任务 → 审查后重新定稿。不得直接批量覆盖后续正文。

### 3.5 灵感与学习

收集灵感或资料 → 去重、分类并记录来源 → 分析与评估 → 形成候选剧情方案或创作方法 → 用户或已授权规则采纳 → 进入规划、文风或任务约束 → 用后续结果检验效果。

## 5. 内容与状态边界

### 5.1 内容分层

- 原始资料：用户输入、原稿、附件及来源记录；保留原貌。
- 灵感与参考：未采纳构想、研究记录、参考知识；明确标注可信度与适用范围。
- 候选成果：待检查正文、候选设定、分析意见、学习成果与变更提案。
- 正式资产：满足适用门禁并完成授权提交的正文、正式设定、文风规则与创作规划。
- 派生数据：摘要、索引、向量、质量报告；能重建，不能取代原文和正式事实。

正式记忆状态：`PROPOSED → CANON / REJECTED`；被替代的 CANON 成为 `SUPERSEDED`。删除采用归档或撤销记录，保留引用与历史。

正文版本状态：`DRAFT → IN_REVIEW → READY_TO_FINALIZE → FINALIZED`，另有 `SUPERSEDED`。门禁情况单独记录为 `PENDING / PASSED / FAILED / ERROR / STALE`。新的编辑创建新草稿版本；旧定稿保留历史，不能被新稿继承通过结果。

旧系统的 `COMPLETED` 仅表示旧工作流完成，迁移时不得直接认定为满足新门禁的 `FINALIZED`。

### 5.2 记忆生效规则

人物状态与事件同时记录故事时间、叙事位置和系统记录时间，支持倒叙、插叙、时间区间和不确定日期。不得仅按章节号判定所有状态。

正式记忆采用用户确认或可审计的显式自动生效规则。初始保守策略：新事实及有争议状态等待确认；格式整理、确定性索引维护等普通技术工作自动处理。后续可授权低风险事实自动生效，重大剧情及核心设定修改仍须审批。

## 6. 决策、权限与自动化

重大变更默认包括：核心世界规则改动、主要人物死亡或身份改写、主线及结局方向变更、跨章大范围重写，以及改变检测硬门槛。重大程度可按作品配置，但执行者不能自行降低级别。

普通问题可按已配置规则自动修正，例如排版、已确认实体名的明确笔误，或约束内的局部措辞调整。确定性较低、证据冲突、关键目标不清楚、改动超出授权范围时创建决策项。

每个决策项至少提供：问题、证据引用、可选方案、建议及理由、影响范围、预计费用、候选版本。建议选项不等于批准；超时不视为批准。审批所依赖的正文、设定或规则变更后，审批过期。

权限以作品、资产集合、任务类型和工具为范围。外部 Agent 使用短期任务凭证，只能提交候选成果。导入资料及执行者文本不具备修改平台指令、预算或权限的效力。

## 7. 质量门禁与朱雀规则

### 7.1 门禁组合

定稿需要同时满足：成果完整、版本仍有效、无未解决的阻断性一致性问题、必要审批完成、适用文学与文风规则通过，以及朱雀人工特征 100%。任一必要检查失败、缺失、过期或异常均阻止自动定稿。

文风偏离可由用户声明为有意创新并记录适用范围；该例外仅影响对应文学或文风规则。朱雀 100% 门槛不得被普通例外、离线规则、其他检测器结果或人工填写分数替代。

未接入真实朱雀的开发阶段允许保存草稿、运行模拟闭环和导出带状态的工作副本，界面必须明确显示“检测未完成／未定稿”。正式定稿及作为定稿的导出复核全部门禁。

### 7.2 朱雀通过标准

基于截至 2026-10-23 核对的腾讯云接口说明，约定标准为：

```text
status == "success"
labels_ratio["0"] == 1   # 人工内容占比
labels_ratio["1"] == 0   # AI 内容占比
labels_ratio["2"] == 0   # 疑似 AI 内容占比
```

必须校验字段齐全、数值范围、结果结构及正文覆盖完整性，使用原始数值，不用显示百分比四舍五入后的值。整体置信度不是人工占比，不能互换。

长章按已验证的接口限制制定完整覆盖的分块清单。所有必检块均须通过，任何一个块失败或未检测均阻断；不得只挑选通过段落、丢弃失败段落或平均稀释风险。分块与整章模式的口径差异需要通过真实样本联调记录，不宣称二者分数等价。段落结果与整体占比矛盾时进入异常复查。

每份报告绑定正文内容哈希、版本、检测提供者、可获得的模型或接口版本、请求参数、分块策略、响应和检测时间；未提供的模型版本标记未知。正文变更或检测策略更新后重新判定有效性，不能沿用旧稿结果。跨版本升级无法识别时，由检测时间及重检策略明确其适用范围。

人工特征 100% 是第三方检测结果门槛。平台保证执行门禁，不承诺任意作品都能通过有限轮次修改达到该分数，也不将通过结果表述为真实作者身份或质量证明。

### 7.3 费用、失败与修改

当前 EdgeOne Makers 朱雀文本接口提供每月 50 万 token 免费额度；接入时重新核对账户规则。配置额度周期与用量预警，按 `makers_models_usage.total_tokens` 核算实际免费额度消耗；`usage.total_tokens` 不用于该额度核算。50 万 token 不换算成固定字数或固定检测次数。

记录检测与重写两类成本。相同版本与有效检测策略可复用完整结果；需要新报告或缓存过期时重新请求。额度耗尽后等待用户选择等待周期恢复、修改预算或其他明确方案；不得静默付费、自动切换检测器或降低门槛。

重写规则包括单步重试上限、每章修订上限、总调用上限、费用及耗时上限、无进展停止条件。具体数值由预算配置提供；未配置必需上限时不能启用无人值守运行。

达到上限、发生文学质量倒退或改动涉及重大剧情时停止自动修改，保留原稿与候选、报告原因并等待决策。用户可决定继续修改或暂停；批准一次继续执行不会自动放宽定稿条件。

## 8. 非功能需求

| ID | 目标 | 验收方式 |
| --- | --- | --- |
| NFR-01 | 百万字规模管理 | 至少 100 万字、500 章、1 万条结构化记忆及 10 万个历史／派生记录的固定数据集；分页、检索与增量更新可用 |
| NFR-02 | 可靠执行 | 注入进程终止、超时、重复回调、截断、租约到期和取消竞态；无重复正式提交、无未授权写入 |
| NFR-03 | 成本可控 | 并发预算预留和结算通过；未知费用保守挂账；在途调用可能发生的费用在界面说明 |
| NFR-04 | 可迁移 | 导出作品、版本、正式记忆、规则、任务与审计及格式版本；更换执行者后继续任务，密钥不进入导出 |
| NFR-05 | 可观察 | 从任务追踪调用、检查点、审批、成果和费用；错误区分可重试、永久失败及等待决策 |
| NFR-06 | 个人服务器安全 | 未登录无法访问私人资产；凭证不下发浏览器或进入普通日志；外部 Agent 越权测试通过 |
| NFR-07 | 可恢复 | 数据库与附件一致备份，异机恢复演练；记录恢复点、恢复耗时与校验结果 |
| NFR-08 | 易用性 | 用户能看清当前进度、阻断原因、待决事项、花费和恢复入口；主要创作流程无须直接操作数据库 |

初始工程目标：在 4 vCPU、8 GB 内存、SSD 的声明环境中，普通分页读取 p95 ≤ 1 秒，任务受理 p95 ≤ 1 秒，限定结果数的索引检索 p95 ≤ 2 秒；5 个交互请求与 2 个后台任务并行测量。外部推理时间、网络往返、文件导入和全量扫描单独报告，不能用其掩盖平台查询延迟。上述为待实测目标，不是当前性能结论。

备份初始目标：日常恢复点目标 RPO ≤ 24 小时，完整恢复目标 RTO ≤ 2 小时；迁移与正式升级前追加备份。单机进程故障以已提交数据库记录和检查点恢复，外部调用可能收费而无法恢复完整输出，需要独立对账。

## 9. 尚待实施时输入的配置

这些事项不阻塞规划：首批模型与 Agent 名单、服务器及域名、备份位置、费用与 token 上限、可自动采纳的低风险规则、资料允许发送的提供者、朱雀账户与真实单次限制。

它们不能被默认理解为无限授权。缺少执行必需配置时可使用测试执行者验证机制，实际调用及生产定稿保持阻断并提示补充。
