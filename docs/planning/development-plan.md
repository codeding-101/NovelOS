# NovelOS 分阶段开发计划

日期：2026-10-23

状态：阶段路线图已开始执行；实时进度见 [执行记录](execution-status.md)。

## 1. 开发原则与版本边界

先建立资产、版本、受控写入和恢复基础，再开放持续自动创作。每个阶段都包含可操作网站入口、后端能力、相关验证及更新后的使用说明，避免只积累接口而无法验证流程。

工程采用现有仓库内增量重组，不重新初始化 Git，不改写历史，不清空工作区，不将现有未提交修改当作可删除内容。实施以普通提交与可回退的数据迁移推进。

内部 Alpha 在 M4 后交付受控执行与正式记忆能力；创作预览在 M7 后形成规划、学习、创作与修订闭环；M8 接通真实朱雀；M9 完成生产验收后才作为首个个人生产版本。预览阶段的模拟通过仅用于验证机制，不能认定正文满足真实定稿门槛。

## 2. 当前仓库评估

基于 2026-10-23 的只读检查，当前仓库包含：

- FastAPI、SQLAlchemy、SQLite 后端和 Next.js／React 前端。
- 模型 Provider 抽象、OpenAI 兼容端点、规则型离线 Provider。
- 人物状态、CANON、事件、时间线、伏笔、摘要、检索和章节完成流程。
- 规划、灵感碎片、文风与质量检查、修订、导出及部分外部笔记集成。
- Docker Compose、后端离线测试及 GitHub Actions 配置。

以上说明有可复用实现，不代表满足新需求或已通过本轮测试。当前 README 和接口存在旧产品定位与不同版本表述；旧章节 `COMPLETED` 状态不等于新定稿状态。新规划先单独落档，M0／M1 再按现状重写入口说明。

当前观察到的未提交内容：

本次不修改这些文件。正式重组前重新核对清单，保存差异及未跟踪文件的副本；不能自动暂存或提交全部工作区文件。

未完成针对新需求的全面代码审计，以下属于实施重点而非断言所有旧模块完全缺失：统一外部 Agent 协议、持久任务与检查点、费用预留、统一审批、不可变正文版本、检测版本绑定、真实朱雀门禁、服务器访问控制与恢复演练。

## 3. 复用和改造策略

| 现有部分 | 处理方向 | 进入新体系前的条件 |
| --- | --- | --- |
| Provider 与兼容端点 | 封装进执行者适配器 | 能力声明、费用、取消及错误契约验证 |
| 人物、设定、事件与伏笔 | 迁移为带来源和版本的记忆模型 | 时点查询、审批、跨作品隔离验证 |
| SQLite 与旧迁移 | 保留旧数据和只读导入能力 | 新库迁移演练、数量／哈希校验与失败回退 |
| 正文文件与导出 | 迁移到单一权威正文与可重建副本 | 不丢原文，明确新旧版本映射 |
| 工作流与 Agent 循环 | 拆成持久任务步骤 | 幂等、预算、取消及故障恢复验证 |
| 文风与特征规则 | 作为可配置分析器评估复用 | 证据、误报反馈、创新例外、策略版本化 |
| 前端工作台 | 按用户流程复用组件 | 增加任务、审批、费用和门禁状态，统一术语 |
| 旧测试和 CI | 保留有效用例并补关键机制验证 | 区分旧行为、兼容行为及新契约；不以旧数量代表新覆盖 |
| 平台投稿规则、笔记同步、读者数据 | 列入可选扩展 | 不成为通用创作平台的固定限制 |

## 5. 阶段工作包与验收

### M0：重组准备与现状基线

工作包：

1. 清点 Git 跟踪状态、未提交修改、数据库、正文文件、附件、启动脚本和配置引用；不打印密钥。
2. 保存代码差异和数据备份，建立原文及附件校验清单；记录当前提交和工具版本。
3. 运行现有适用的后端测试、前端构建和 Compose 冒烟，记录可复现失败与已有问题。
4. 完成功能复用、行为冲突、数据迁移及可选扩展清单；确定第一批小工作包。
5. 核对远端仓库与本地分支关系；后续使用 `codex/` 开发分支和普通增量提交，已有修改的归属单独处理。

交付：基线报告、备份清单、旧行为记录、模块改造清单及阶段估时。

退出标准：未提交内容和原始资产有可验证副本；现有系统能重现启动或有明确失败记录；不能为了获得绿色结果删除旧测试或数据。

### M1：服务器与持久化基础

工作包：

1. 建立模块边界、配置加载、统一错误结构、API 版本和数据库迁移机制。
2. 建立 PostgreSQL 新库，编写 SQLite 只读导入骨架与版本映射，保留旧库。
3. 建立单用户登录、会话保护、服务端凭证管理及独立 Agent 凭证模型。
4. 拆分 Web、API 与 Worker 启动入口，配置内部网络、HTTPS 入口和健康检查。
5. 提供登录、部署状态和基础设置页面，更新开发与部署文档。

交付：可登录的服务器应用骨架、迁移工具、部署配置和架构决策记录。

退出标准：未登录请求无法读取作品与配置；密钥不出现在客户端包和日志；空库可初始化；升级预检可阻断不兼容库；重建容器后持久数据仍在。

### M2：作品、版本与审计

工作包：

1. 管理作品、卷章场景、原始资料和附件；实现 Markdown／TXT 基础导入。
2. 实现不可变正文版本、差异比较、恢复及乐观并发控制。
3. 实现数据库权威正文、文件存储适配器、导出清单、outbox 与索引重建入口。
4. 建立操作审计、资产引用和依赖边；完善旧资产导入映射。
5. 网站提供作品列表、编辑器、历史与恢复预览。

交付：作品资产服务、版本 API 与可操作编辑器。

退出标准：旧稿导入导出后内容哈希匹配；冲突编辑不静默覆盖；恢复创建新版本；跨作品引用被拒绝；文件或索引失败可以重试且不丢正式原文。

### M3：执行者与可恢复任务控制

工作包：

1. 实现 TaskEnvelope／ResultEnvelope、schema 版本、执行者注册与能力声明。
2. 首先交付测试执行者、人工执行任务、通用兼容模型适配器和参考外部 Agent 客户端；真实提供者依用户配置。
3. 实现持久任务、依赖、队列、优先级、租约、心跳、attempt、检查点和幂等提交。
4. 实现暂停、取消、有限重试、失败分类、未知费用对账及过期租约隔离。
5. 实现预算预留、结算去重、用量查询和能力／权限／预算路由。
6. 网站提供执行者设置、任务中心、进度、费用和恢复操作。

交付：API、Agent、人工三类执行路径及可恢复任务控制。

退出标准：执行一个任务后终止 Worker 并重启，可从有效步骤恢复；重复上报只保存一次有效候选；迟到旧 attempt 无权提交；预算不足不新增调用；截断结果不标成功；没有密钥不会伪装为真实创作成功。

### M4：正式记忆、上下文与审批

工作包：

1. 实现人物、关系、世界规则、事件、故事时间线、伏笔与承诺的版本与来源。
2. 实现候选提案、CANON 生效、替代、历史视图和倒叙／插叙时点查询。
3. 实现检索、分层摘要、上下文快照和必需信息容量检查；支持中文检索评估样本。
4. 实现权限和审批规则、重大变更分类、人工决策项和审批过期检测。
5. 建立统一正式提交服务及可插拔门禁；初期真实检测缺失时定稿保持阻断。
6. 网站提供记忆浏览、证据定位、审批中心和上下文查看。

交付：可审计正式记忆与任务上下文，形成内部 Alpha。

退出标准：候选事实不进入正式检索；任意执行者无法直接写 CANON；审批过期不能应用；必需上下文超限会明确阻断；旧 `COMPLETED` 不升级为新定稿；旧 API 不能绕过受控写入。

### M5：规划与 AI 持续创作

工作包：

1. 支持全书、分卷、章节和场景目标，以及人物弧线和伏笔计划。
2. 将规划、研究、创作、抽取、检查、修改与提交拆成可恢复任务图。
3. 实现单章运行和受范围、费用及任务数限制的多章自动运行。
4. 新信息、冲突和重大剧情变化进入审批；用户反馈转成明确任务约束。
5. 网站提供创作目标、计划板、章节进度和连续运行控制。

交付：AI 主导、用户辅助的创作流程预览。

退出标准：测试故事可从规划生成多章候选；用户关闭浏览器不终止后台任务；在审批或预算处暂停后可继续；更换执行者保留资产与任务进度；未通过真实检测的正文仍为未定稿。

### M6：灵感、资料学习与经验

工作包：

1. 实现灵感收集、去重、关联、评估、候选融合方案和采纳跟踪。
2. 首批支持 TXT／Markdown 资料与可追溯文本摘录；PDF／DOCX 解析作为可插拔后续工作包，原附件始终可保存。
3. 实现外部执行者分析资料并提交有来源的学习成果，区分知识、创作方法和故事设定。
4. 建立经验候选、启用、范围、效果反馈和撤销流程。
5. 为资料设置允许外发提供者，网站显示采纳状态与影响位置。

交付：灵感库、资料库与可复用学习成果。

退出标准：未采纳灵感不自动成为剧情；资料中的指令无法改变平台权限；学习成果能定位来源；被禁用经验不进入新上下文；不允许外发的资料不会发送给该执行者。

### M7：质量、文风、修改与变更修复

工作包：

1. 建立文风样本、可解释指标、人物声音及叙述阶段档案。
2. 复用并校准句式重复、套路和跨章同质化分析器，结合模型审查文学质量。
3. 建立带证据的问题、严重级别、驳回理由与有意创新例外。
4. 实现逐轮候选修订、质量退步保护、次数／成本／耗时及无进展停止。
5. 实现早期设定变更影响图、报告失效传播、修复任务和关联记忆恢复。
6. 网站提供问题定位、版本比较、修订轨迹和影响处理面板。

交付：完整创作与有界修订预览，附质量回归样本。

退出标准：规则发现的问题均有可定位证据或明确标注模型建议；创新例外不改变朱雀要求；设定修改使已知依赖报告过期；疑似影响不冒充完整因果追踪；重写触顶会停机待决；回滚不遗留冲突的现行记忆。

### M8：腾讯朱雀与严格定稿门禁

工作包：

1. 重新核对 EdgeOne Makers 接口、账户额度、限流、输入上限、字段语义和可用模型信息，形成适配记录。
2. 实现服务端朱雀适配器、超时与错误分类、限流、用量账本和额度预警。
3. 实现全章覆盖清单、必要分块、报告绑定、有效期与缓存规则。
4. 对接未达标后的复查、候选重写、复检和停止条件，费用同时计入总预算。
5. 在统一定稿事务及正式导出中强制检查真实检测与所有其他必要门禁。
6. 网站展示检测范围、原始占比、分块、额度、阻断原因与待决操作。

交付：真实朱雀接入和可审计的 100% 定稿机制。

退出标准：

- 契约用例覆盖人工占比 1、0.99999、字段缺失、异常结构、检测错误、检测结果相互矛盾和部分分块失败。
- 仅完整且有效的真实结果满足人工 100%、AI 0、疑似 AI 0 时，该项门禁通过。
- 四舍五入、旧正文报告、缺少检测块、离线替代和重复账单不能绕过检查。
- 超额、限流、服务中断及未知计量能够暂停并恢复，不自动付费或放宽门槛。
- 使用用户提供的凭证完成小额、有限量真实联调，保存脱敏证据；真实文本若未达标，必须正确阻断。

机制验收不以“任意测试小说经过固定轮数必达 100%”为条件。真实通过路径在取得服务端有效通过结果时验证；固定 fixtures 只用于状态与错误分支测试，不充作生产检测证据。未完成真实联调前不能宣称正式生产接入完成。

### M9：规模、故障恢复与个人生产版本

工作包：

1. 生成固定百万字测试集，包含记忆、旧版本、任务、伏笔及已知矛盾；测试不依赖付费生成百万字。
2. 测量查询、检索、导入、增量重建、内存和并发预算，定位实际瓶颈。
3. 演练 Worker 强停、服务器重启、外部调用超时、重复回报、取消竞态和迁移失败。
4. 完成数据库与附件一致备份、异机恢复、凭证恢复及暂停后人工恢复调度。
5. 完成权限、资料隔离、上传、日志脱敏与公网部署检查。
6. 演练一部作品从建档、创作、审查、检测、审批、定稿到变更修复和导出的端到端过程。
7. 更新 README、部署与维护指南、迁移说明、已知边界、需求验收映射及发布说明。

交付：首个个人生产版本、验收证据、可恢复备份与维护手册。

退出标准：需求规格 NFR 的目标通过或有明确未通过项；阻断需求未通过不得标为生产完成；百万字规模只证明管理与性能，不宣称故事质量或自动消除所有矛盾。

### M10：长期扩展

按用户实际使用反馈增加模型及 Agent 适配器、PDF／DOCX 等资料解析、跨作品经验审核、更多中文检索与嵌入方案、可选笔记集成和投稿平台规则。队列、对象存储或服务拆分以实测瓶颈为依据。多人协作或商业化另立需求，不静默扩大首版范围。

## 7. 验证分层与完成定义

只为关键业务机制建立有意义的测试：状态和权限、版本并发、幂等、预算、审批、候选与 CANON 隔离、检测覆盖与数值、修订停止、恢复与导出。普通文案和目录调整进行差异检查即可。

验证分层：确定性单元与契约用例 → PostgreSQL 集成与故障注入 → 前端构建及关键流程冒烟 → 有预算上限的真实外部联调 → 百万字与恢复演练。离线 fixtures 和真实服务证据分别记录，不将网络依赖引入普通 CI。

每个工作包完成需要：

1. 可核对的用户行为、契约与状态变化已实现。
2. 对应关键验收通过；测试环境、结果和已知限制有记录。
