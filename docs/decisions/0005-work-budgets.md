# ADR 0005：作品累计预算、调用预留与未知费用

日期：2026-10-24。状态：采用，M3 预算基础工作包。

## 背景与选择

持久任务的成功／失败不能说明供应商是否计费。取消、超时和进程崩溃后若自动释放所有额度，会让重试绕过预算；重复回执还可能造成重复扣账。因此将调用账目与创作结果分开管理，并先提供可离线验收的事务边界。

每部作品建立一个全生命周期账户，固定 CNY 或 USD，同时限制费用与 token 总量。采用整数微单位和数据库 BigInteger，不做浮点累计或自动汇率转换。默认未配置不允许外部调用，当前人工和本地校验不计模型消费。

## 核心约束

- `WorkBudget` 是余额投影；`BudgetReservation` 记录单次调用状态和实际用量；`BudgetEvent` 是不可变事件及余额快照。数据库触发器禁止改写和删除事件。
- 调用按 RESERVED → DISPATCHED → SETTLED 流转。确定未登记发起的预留才能 RELEASED；可能已到达供应商的中断调用进入 UNKNOWN，保持占用，直到取得明确用量依据。
- 所有预算变更在短事务中完成，锁顺序为任务 → 作品预算。预留与可用额度检查串行化，跨任务竞争不会共同超额。网络请求在事务外，且只能发生在成功提交 DISPATCHED 后。
- 同一 attempt 的 operation_key 只创建一笔预留；重复登记不授予再次发送权。同一执行者的 receipt_key 不能在不同调用或作品重复计费，数据库唯一约束处理跨作品并发冲突。
- 费用未知时冻结该作品的新预留和登记发起；暂停／取消／过期恢复与账本同事务处理。未知费用的任务不能恢复；对账不自动修改任务状态或正文。
- 实际费用超出预留时如实记账并标记差异，禁止把金额压到预算上限伪造安全。降低预算也不抹去历史余额；新调用检查降低后的总额度。
- 人工对账需要未知状态、预留版本、实际金额、输入／输出用量及非空依据。已结算内容不能覆盖；重复相同回报幂等。当前不提供冲正，后续若需要必须追加审计事件。

## 范围和代价

作品累计预算避免在未接入供应商计量前假定月度重置语义。后续须另外实现供应商免费额度、单任务子预算、价格上界、路由选择、真实账单解析和对账工具。当前字段不能冒充朱雀的月度配额或真实检测结果。

先提交登记再调用，可能出现“已登记但实际未发送”的不确定状态；选择保留额度并要求核对，避免重复发送。这是保守会计记录，不承诺端到端外部请求恰好执行一次。真实适配器还须处理供应商幂等键、传输超时与最大生成限制。

已有人工任务协议的零用量和权限保持有效。预算内部钩子尚未接入真实 API／Agent，保存配置不会启用调用。当前阶段与验证证据见 [执行记录](../planning/execution-status.md)，操作说明见 [预算指南](../operations/work-budgets.md)。
