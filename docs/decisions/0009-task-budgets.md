# ADR 0009：跨执行尝试的任务累计预算

- 状态：已接受
- 日期：2026-10-25

## 背景

作品预算限制总消费，但单个反复修订的任务仍可能占用全部作品额度。任务重试必须继承已发生费用及未知占用；取消或缩小额度也不能掩盖已有费用。

## 决策

任务保存固定币种和可调整的费用／token 上限，账目直接从已有调用记录聚合，不建立第二套可漂移的余额。预留与发送继续遵循任务锁、作品预算锁顺序，并在事务内同时检查两层额度。领取和恢复提前检查下一次冻结计划，避免预算不足消耗尝试。

新模型任务默认上限为单次计划预留乘以最大尝试次数，可由用户显式指定；作品上限始终独立生效。任务额度不是作品额度的预分配，也不是供应商保证。配置修改绑定任务版本并记录前后值审计，不自动恢复调度。

历史任务的新增字段保持为空，继续执行前要求补充额度。创建幂等哈希忽略未提供的新字段，防止升级使原请求失效；历史账目与路线记录保持不变。

已发送／未知调用保留占用，真实上报的超额仍须入账。降低上限只能阻止后续操作，不能撤回已经发出的请求。任务已结束后不开放额度修改。

## 验证与限制

SQLite 与 PostgreSQL 验证并发预留、跨尝试累计、领取阻断、发送前重检、未知对账、超额结算、版本冲突及历史库升级；浏览器验证创建、恢复、双页面冲突和累计展示。

本决策不开放真实模型调用。当前模型协议仍只在隔离测试环境连接本机模拟服务；用户明确要求暂不开放真实调用。月度额度与供应商账单仍属后续工作。
