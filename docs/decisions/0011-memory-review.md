# ADR 0011：不可变记忆提案与受控生效

- 状态：已接受
- 日期：2026-10-26

## 背景

正文、任务候选和正式记忆必须区分。候选产物中的事实不能自动成为 CANON；用户审核时看到的来源或当前记忆若已变化，旧批准也不能覆盖新版本。

## 决策

采用不可变提案、来源绑定、审核决定，加一份现行正式指针的模型。提案保存完整内容、作品内稳定标识、类型、依据版本、可选任务候选和有效期；批准才创建或推进正式指针。候选列表与正式查询采用独立路径，不把未批准或已驳回内容混入正式检索。

所有变更先由用户审核。批准在作品事务锁下进行，并按资产 ID 顺序锁定来源行；资产编辑也更新同一行。随后复查来源版本、现行正式依据和期限，决定、正式指针与审计同事务提交。并发提案只有一个能替换同一依据，失败不产生半次生效。

幂等创建绑定作品及请求键；幂等审核绑定提案、决定和理由。重交已保存的旧批准只返回历史决定，不回写现行指针。提案、来源绑定与决定使用数据库不可变保护。已批准来源后续变化只标记需复查，保留审批及证据，不擅自撤销创作事实。

此工作包不开放 Agent 直接提交或批准正式记忆。已接收任务产物可由用户关联，但必须属于同作品并引用原输入版本，隔离及不完整候选不能作为该关联来源。记忆文字和资料中的指令不拥有平台权限。

## 验证与边界

SQLite 与 PostgreSQL 验证候选隔离、跨作品拒绝、来源失效、期限、并发批准、源编辑锁后复查、旧批准不回退、事务回滚、来源哈希和不可变历史；浏览器验证来源预览、修改前后、审批冲突保留输入及页面布局。

这是依托已验收持久任务／资产能力的 M4 离线基础，不将 M3 尚未完成的真实联调标为通过。类型当前用于分类文字记忆，结构化时间状态、上下文快照、重大变更分类和正式正文提交继续分包实施。批准记忆不等于小说定稿，真实调用及朱雀门禁边界不变。
