# ADR 0006：声明式执行者与可审计的本地路由

日期：2026-10-25。状态：采用，M3 路由基础工作包。

## 决策

将执行者登记、配置检查和实际执行权限分开。登记只记录声明能力、用户标记可用状态、价格、上下文上限及凭证引用。外部 API／Agent 的适配器状态由平台决定，用户填写配置或启用声明不能解除 `ADAPTER_NOT_READY`。

作品保存允许列表、首选顺序和是否允许自动使用本地诊断的开关。默认允许两个内置执行者，自动首选人工，诊断不自动参与。任务显式指定执行者也遵守作品允许列表；自动选择仅使用符合能力、启用和可用条件的项，按首选、优先级、稳定标识排序。

数据库新增 `execution_policies` 和 `task_routing_decisions`，扩展 `executors`；通过 `0006_executor_routing` 显式迁移。新任务的选择依据随任务创建同事务落库，并以触发器禁止改写或删除。旧任务不补造历史选择快照。

创建任务按作品、执行者顺序加锁，锁后重新计算；自动选择发生变化时返回冲突。领取时在任务锁之后按相同顺序检查当前规则，不满足则暂停且不消耗尝试。作品规则更新只锁作品，执行者更新只锁该项。登记通过 owner 锁串行化上限和幂等键检查。

执行者和规则采用乐观版本检查，登记采用独立请求幂等键。用户修改声明不改变已在执行任务的输入或凭证，停止当前工作仍使用暂停／取消。排队任务固定到创建时的选择，不自动改派；未来提供跨执行者恢复时须建立新的尝试和明确上下文迁移记录。

预算检查复用已结算、预留和未知费用状态，但检查本身不预留额度。输入／输出价格用整数分别向上取整，保持币种隔离。真实适配器必须在发送前做保守估算、权限检查和预算预留，不能把本次配置预览当成授权。

## 取舍和边界

手工声明能力和可用性满足当前个人平台配置需求，不等于自动能力发现或健康探测。允许注册未来执行者有助于检查配置和作品规则，但接口不暴露网络地址或实际调用入口，避免把注册成功标为已接入模型。

本地诊断需要独立的自动选择授权，防止分析任务被静默降级为字数统计后误报模型完成。它只能声明 `analyze`，无法匹配创作或修订。真实 AI／Agent 的能力验证、身份、调用协议和预算计量仍由后续工作包完成。

验证覆盖并发登记、版本冲突、无可选执行者、诊断显式选择、排队任务重新检查、排序变化回滚、费用取整、预算不足、未知费用、凭证删除以及外部适配器阻断。网站验证登记与规则持久化、排除原因及自动任务完成；具体结果见 [执行记录](../planning/execution-status.md)。
