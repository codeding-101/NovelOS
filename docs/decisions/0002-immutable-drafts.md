# ADR 0002：草稿版本的权威存储与冲突保护

日期：2026-10-24。范围：M2 的作品编辑与版本工作包。

## 决策

`works` 保存作品信息，`assets` 保存卷／章／场景／资料的稳定标识、父级和当前版本号；`asset_revisions` 保存不可变标题、正文、SHA-256、版本号、创建时间及恢复来源。每个资产的版本号唯一。现阶段所有版本只能为 `DRAFT`，API 不接受调用方提供其他状态，数据库检查约束再次限制状态。

写入在一个数据库事务中完成：比较调用方的 `expected_version`，原子增加资产当前版本号，追加版本及审计。失败、冲突或回滚不留下版本和成功审计。SQLite 与 PostgreSQL 的数据库触发器禁止修改或删除版本和原始导入文件记录，避免后续应用代码意外覆盖历史。触发器不是针对数据库管理员的权限隔离措施。

父级结构在创建时验证：同作品的卷可包含章，同作品的章可包含场景；资料位于作品下。当前不提供移动、删除或重排接口。跨作品资产或版本引用返回不存在。一般资产依赖边在后续 M2 工作包实现，不将父子结构冒充完整影响图。

TXT／Markdown 导入与原始字节保存属于同一事务。`original_uploads` 在此阶段使用数据库二进制列保存至多 2 MiB 的原文件，避免在文件系统和数据库之间产生未处理的半提交。数据库中的正文是权威来源，不进行双写文件镜像。完整文件存储适配器和事务 outbox 属于后续工作；这里没有隐含宣称它们已完成。

导出捕获资产当前版本号，随后读取这些版本号以内的不可变历史；并发追加不会改变此次导出。文件名使用生成的标识，清单保留显示标题、源文件名和校验值。ZIP 使用可溢出到临时文件的缓冲，并有总大小及文件数量上限。导出只是草稿快照，不能使内容定稿，也不是全平台灾难恢复备份。

## 验证重点

- SQLite 与真实 PostgreSQL：M1 升级保留账户和凭证；并发提交仅一个成功。
- 事务中止后正文、版本号和审计均回滚；历史记录在数据库级拒绝覆盖和删除。
- 导入原稿与导出原文件、正文哈希一致，包括 BOM 和不同换行。
- 跨作品读取、父级、比较与恢复被拒绝；未登录和无 CSRF 写入被阻断。
- 浏览器验证冲突后保留输入、恢复生成新版本、手机布局和下载。

实际验收状态以 [执行记录](../planning/execution-status.md) 为准。M2 全阶段仍需完成余下工作包才能退出。
