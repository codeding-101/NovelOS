# ADR 0013：不可变离线上下文与显式容量取舍

- 状态：已接受
- 日期：2026-10-27

## 问题与决策

任务准备需要可重现的目标、正文与正式记忆，不能在每次查看时暗中换成最新内容。容量不足时必须保留诊断依据，明确哪些必需信息导致阻断、哪些可选信息被省略。

增加不可变 `context_snapshots` 和 `context_memories`。快照保存确切 JSON 文档、UTF-8 字节数、SHA-256、创建配置指纹、保存时 READY／BLOCKED 状态与原因；记忆选择记录固定版本、必需标记、顺序、纳入决定及省略原因。正文始终完整必需，所有必需记忆优先，随后按输入顺序完整尝试可选条目，不裁剪字符或伪造摘要。

用户显式选择现行批准记忆。候选、驳回、旧版本和跨作品引用拒绝创建；现行但来源已变化、故事时点不符或容量不足，以必需／可选角色分别阻断或省略。空时点不做区间筛选，无时点文字条目不补造时间。此方案先实现确定性的显式选择，不声称实现自动召回或完整核心事实识别。

创建按作品锁 → 所有相关资产的排序锁集进行，避免输入和记忆来源共用资产时出现反向锁顺序。快照、选择及审计同事务提交；数据库触发器禁止更新／删除，约束禁止 READY 超限或必需项被省略。原文不写入普通审计详情。

读取快照保留原文档，动态附带依据状态；显式复查在同类锁下校验实际纳入项并记录审计。复查结果是观察，不是执行授权；省略项与未选择的新事实不在固定依赖集内。真实任务消费者的绑定及领取、发送、提交时复查继续作为后续独立工作包。

## 容量语义与兼容

本地容量定义为完整序列化文档的实际 UTF-8 字节，不等于模型 token 或窗口。未接入真实供应商时，避免用启发式字符数宣称可保证供应商容量。后续分词、输出预留、提示模板及执行者限制必须另行验证。

迁移只增加新表，不改变既有任务协议、Agent 权限、预算、正文与正式记忆，不隐式创建历史快照。快照组装成功也不会触发真实调用或授予定稿。分层摘要、语义检索、中文检索评估与完整 M4 仍待后续。
