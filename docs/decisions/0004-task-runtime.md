# ADR 0004：持久任务、执行尝试与候选隔离

日期：2026-10-24。状态：采用，范围为 M3 首个工作包。

## 背景

M2 提供不可变作品版本。任务若只存在于进程或对话中，断网、重启、重复回报和取消竞态会丢失进度或错误覆盖正文。先建立可离线验证的执行边界，再接入需要预算的真实执行者。

## 决策

- 任务、执行尝试、检查点、依赖与提交回执存入平台数据库；schema 通过 `0004_task_runtime` 显式升级。旧业务库不参与。
- 使用版本化 `TaskEnvelope`／`ResultEnvelope`。输入固定绑定单个不可变版本，在领取和成功提交时检查仍为当前版本；后续多资产上下文须显式扩展协议。
- SQLite 和 PostgreSQL 均通过短事务中的条件写锁串行化任务变更。控制操作携带任务版本；领取凭证哈希、尝试标识与期限共同验证执行权。取消／暂停使旧尝试失效，接续轮换凭证。
- 任务到结果遵循“允许重复传输、只接收一次有效成果”。创建、检查点和结果分别使用幂等键，改变同键内容会冲突。结果、状态与审计同事务提交。
- 候选是独立不可变结果，不写正文或正式记忆。迟到、输入过期和超出输入／产物范围的结果隔离保存；不完整结果保留并暂停。
- 依赖只允许新任务引用已存在的同作品任务，依赖边不可变，从结构上排除循环。调度先过滤未满足依赖再限制候选数量，防止高优先级阻塞任务遮挡其低优先级前置任务；这不承诺高负载下的通用公平调度。
- 尝试次数、总期限、单次期限、检查点和结果大小／数量均有限制。人工中断暂停等待用户恢复；本地临时失败有限退避重试。跨尝试读取最新检查点，执行者验证其内容后再复用。
- 当前仅内置人工和本地确定性诊断执行者。网站人工领取沿用用户会话及 CSRF，不能把保存的供应商凭证或现有 Agent 凭证模型当成任务执行权限。
- Worker 每轮分别处理资产派生同步与任务恢复／本地执行；某一处理步骤失败不会跳过另一步。错误日志仅记录步骤与异常类型。

## 取舍与后续

数据库队列适用于当前个人平台，避免在任务状态与队列消息之间引入双写。任务规模、吞吐与公平性在 M9 实测后再决定是否增加外部队列；短事务锁定不代表已经完成百万字或大规模任务压测。

当前固定单输入、两个执行者、零外部用量，不能冒充完整执行者路由或预算账本。M3 后续必须提供预算预留／对账、能力和可用性选择、外部调用不确定状态及受限 Agent 认证。任务成功只意味着契约内候选接收；采纳、正式记忆审批、质量和朱雀定稿门禁由后续阶段处理。

验证包括 SQLite／真实 PostgreSQL 的并发领取与取消竞态、失败回滚、有限恢复、迟到隔离、不可变记录，以及网站端接续和正文保护。当前验收范围见 [执行记录](../planning/execution-status.md)，使用说明见 [任务中心指南](../operations/task-runtime.md)。
