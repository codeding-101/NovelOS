# ADR 0001：独立控制平台入口与受控迁移

日期：2026-10-23

状态：M1 已实施，部署验收状态见执行记录。

## 背景

旧应用将章节、规则分析、模型调用、SQLite 初始化和文件镜像放在现有运行入口中。工作区另有用户未提交修改，且旧库保存真实作品。直接替换旧数据库初始化或一口气搬迁所有业务模块，会把控制基础与作品迁移耦合。

## 决策

新增 `app.platform` 作为控制平台基础模块，以 `app.platform.api:create_app --factory` 为新入口；旧 `app.main:app` 保留用于旧系统和回归测试。生产镜像仅启动新入口，新入口不注册旧业务路由。

新平台使用独立 SQLAlchemy metadata、Alembic 版本和数据库。生产使用 PostgreSQL，SQLite 只用于本地开发与测试。M1 不复制旧作品，提供只读盘点命令及原文哈希；M2 再引入作品和不可变版本领域。旧 `COMPLETED` 的迁移目标首先为草稿，不能继承新定稿资格。

数据库迁移通过显式 CLI 或 Compose 一次性 migrate 服务执行；API／Worker 启动只校验版本。不接受无 Alembic 标记的已有非空库，不支持破坏性 downgrade。旧库不作为新库初始化目标。

个人账户采用 Argon2id 密码哈希和数据库会话。Cookie 仅保存随机会话值，数据库保存其摘要；写操作同时校验会话、CSRF 和请求来源。生产 HTTPS 使用 Secure、HttpOnly、SameSite Cookie。登录限流通过数据库原子计数，进程重启不会清空。

供应商凭证用 Fernet 加密后入库，主密钥由部署环境提供。外部 Agent 凭证使用独立表，未来仅授予任务范围权限；M1 不接受 Agent Bearer token 访问个人控制接口。

Worker 入口独立，M1 仅实现心跳与正常停止状态，不声称具备 M3 的任务领取、重试或恢复功能。控制台通过能力字段说明尚未开放的功能。

## 影响

- 旧业务测试继续运行，重组期间不会把用户未提交修改混入新的基础模块。
- 前端首页切换为登录与控制台；旧工作台作为待复用组件保留，不再由新平台公开直接访问。
- 新旧数据库暂时并存。后续模块优先进入新平台的领域边界，不能借兼容接口绕过审批和门禁。
- 主密钥必须随备份另行保存；更换或遗失会使已存凭证无法解密。主密钥轮换属于后续明确工作包。
- M1 尚不实现作品备份恢复和任务检查点；这些能力分别由 M2／M3／M9 继续建设。

## 依据与验证

[Alembic 迁移命令](https://alembic.sqlalchemy.org/en/latest/api/commands.html)、[Argon2 密码接口](https://argon2-cffi.readthedocs.io/en/stable/api.html)用于核对库的使用方式。实际兼容性由 SQLite 与 PostgreSQL 集成测试、前端构建和浏览器流程验证。
