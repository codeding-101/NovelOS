# ADR 0010：共享月度配额与固定调用归属

- 状态：已接受
- 日期：2026-10-26

## 背景

作品和任务预算均为累计额度，不能表示多个作品共用的账户月度 token 上限。每个执行者单独授予额度可能重复计算同一账户；月初清空未知费用又可能容许未经确认的重复消费。

## 决策

新增共享配额表、执行者固定绑定和不可变的调用月份记录。配额按用户选择的 UTC 或固定 UTC+08:00 自然月计量输入与输出 token 之和。数据来自现有调用账本，采用“本月已结算 + 所有月份未结占用”，不建立第二套消费余额。

首次预留固定月份，跨月未发送的预留不得直接发送；已发送或未知的用量继续占用，UNKNOWN 阻断整个共享配额。迟到结算按预留月份入账，超额用量照实记录。月份变更无需删除或重置账本，也无需另一个定时重置任务。

写入锁顺序为任务、必要时作品路由行、执行者、共享配额、作品预算。配额绑定采用执行者再配额的顺序，配置修改只锁配额。跨作品或不同执行者的并发预留最终在同一配额行串行检查；首次绑定与首次调用不能竞态绕过计量。调用、归属、额度版本及既有账本在同一事务提交或回滚。

历史执行者不补造月度归属；已有调用记录不得补绑。当前不支持解绑、改绑、删除或更换时区。未绑定的执行者仍沿用作品及任务预算，用户需明确同一账户的共享关系。配置修改采用版本检查和审计，调额不恢复任务。

## 边界与验证

配额是本地控制，不保证供应商账期或剩余免费额度；不抵扣费用、不自动转付费、不统计平台外用量。本工作包不改变真实调用关闭的用户要求，也不替代 M8 的朱雀计量、真实检测和定稿门禁。

SQLite 与 PostgreSQL 验证跨作品和不同执行者并发、绑定竞态、月界和跨年、旧月未发送／未知／结算、实际超额、三层限额、回滚、不可变归属及历史升级。网站验证绑定持久化、累计展示、耗尽阻断、版本冲突及移动布局。
